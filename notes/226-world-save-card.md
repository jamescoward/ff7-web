# #226: an in-game save from the world map writes a valid card

Status (2026-11-20): **fresh attempt 1 passes**: a pad-input save from the world map writes a card whose new save has a right checksum (save-boot-20a). Confirmed by a second Tier 2 run at `7e0b524` (95 pass, 0 fail; 20a identical).

## Why the world map
#131 wants a save at the first save point. No reachable source places that save point (#38, #80), and the route to it from md1_1 is #120's open blocker. FF7 lets the player save anywhere on the world map, and `disc1-wm1-kalm` (#80) boots there with the map live (#140). So this slice proves that the card the game writes is valid, without a save point (agent default, Trip mode rule 11, recorded on #226).

## Sources (reference only; no code copied)
- Card layout and checksum: the generator's own (`runner/savegen/layout.js`, `checksum.js`, notes/32-save-format.md). The checksum is still the CRC-16/GENIBUS hypothesis, but the game has accepted it in every save boot since #38. If the game's own save reads `c_sum 1`, that is a second, independent confirmation: the game computed it.
- Main-menu Save row: `semantic/menus.js` `main` (10 rows and wrapping confirmed by #111; the label order, with Save as row 9, is a source claim, not checked row by row).
- Window 0 state, g_GameState and menuCursor: confirmed entries (#108, #76/#80, #78).

Tier 1: `runner/test/unit/format2-card.test.js` (loader) and `runner/test/tier1/format2.test.js` "card checks" (real core, pad-echo with a blank card: nothing changes, so it fails with zeros; a timeout fails it).
