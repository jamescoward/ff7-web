# M1.5 rescope (owner-approved, 2026-11-04)

Tracking issue: #52.

This was reviewed before work started on the next M1.5 issue. The owner agreed to every point below.

## Where M1.5 stood
- **Done:** #31 (card slot and snapshots), #32 (save generator), #33 (sandbox and attack tests), #34 (validator), #39 (reviewer), #40 (CI benchmark tests), #43 (pad-echo baseline).
- **Stop condition met.** M1.5's stop condition ("the sandbox cannot be shown to block network egress and credential access") is answered by #33's attack tests.
- **Remaining:** #35 (workflows), #36 (disc boot smoke test), #37 (boot from a generated save), #38 (first generated-save scenario).

## Findings
1. **#37 depended on itself.** Loading slot 1 by input means waiting on the title screen, the game mode and "field loaded". Those are M2 addresses, and finding them is what Tier 2 is for.
2. **The Tier 2 loop is narrow by design.** Only pass/fail and up to 8 number metrics per scenario leave the sandbox, and each try is a push, a build, a ~700 MB disc download and a run. That works for confirming candidates, but it is a costly way to debug a menu input sequence blind.
3. **#38 rested on unchecked guesses.** The checksum, the directory file name and some header fields are hypotheses (`notes/32-save-format.md`). A "corrupt save" result says something is wrong, not what.
4. **A cheaper first path exists.** Boot the disc, take one snapshot, then script New Game into the opening. That reaches the first M2 targets (mode, field ID, position, a battle) without a generated save.
5. **The disc pipeline in the browser is already proven.** The owner booted the disc from a preview link on the iPhone, and it ran flawlessly. That covers M1's private "boot the disc" step. #36 is still needed, for the automated pipeline.

## Decisions
- **M1.5 ends when #36 passes.** #35 is unblocked: #33 and #34 are merged and the R2 secrets are in an environment. Its PR still needs the owner's review, because it touches protected paths.
- **#37 is rescoped and moved to M2.** It becomes format 2: boot the disc, take a title snapshot, run input scripts with `wait.until` memory conditions. Nothing but pass/fail and the allowed number metrics leaves the sandbox.
- **#38 moved to M2.** It now includes booting from a generated save (the old #37 steps 1, 2 and 4). It waits for #37 and for confirmed title, mode and field addresses.
- **The Tier 2 result format is unchanged.** The draft review suggested allowing short number series for address work. That would widen what can leave the sandbox, which is a protected trust-boundary change. If 8 metrics per scenario turn out too few in M2, propose it as its own `needs-owner` issue.
- **Meanwhile:** #50 (flaky WebKit audio test, which weakens CI as a gate), then the touch-UX issues #23 and #24. They need no memory reads and are the first user-visible progress since M1.
